# Подготовка, материалы и память сессии

## Для пользователя

Откройте **Разделы → Подготовка и тренировка**.

1. Добавьте материалы: резюме, проект, опыт или описание вакансии. Указывайте только реальные факты. Вакансию можно прочитать по ссылке HH; вход/CAPTCHA выполняются вручную. Этот шаг не отправляет отклик.
2. Отметьте материалы, которые можно использовать сейчас (до 20). Нажмите **Подготовить поиск**. Первый запуск скачивает multilingual MiniLM; дальнейший поиск работает локально на CPU, не занимает GPU распознавания речи.
3. Для чата выберите роль по резюме или свой промпт в настройках помощника, затем нажмите **Применить и открыть чат**. Можно общаться текстом без включения микрофона. Старт голосовой сессии также создаёт отдельную память.
4. Для плана выберите материал типа «Вакансия», затем **Составить план подготовки**. Это шесть запросов ИИ: основы, практика, архитектура, отладка, эксплуатация, проекты/коммуникация. Готовый план содержит ровно 30 разных вопросов, ответы и чеклист. Скачайте `.md` перед уходом из раздела: план не сохраняется автоматически.
5. Для тренировки введите вопрос и свой ответ либо выберите вопрос из плана. **Оценить мой ответ** даёт учебную оценку 0–10, объяснение, улучшения и пример. Это не прогноз найма и не объективный экзамен.

## Данные и ограничения

- Материалы сохраняются в локальной SQLite. Qdrant-индекс существует только в RAM; после перезапуска он собирается из выбранных материалов. Отдельного сервера/Docker/порта Qdrant нет.
- Векторизация локальная, но выбранные фрагменты и вопрос отправляются выбранному ИИ. Контакты частично очищаются по шаблонам; это не полноценная DLP-проверка.
- Сохранение новых сессий выключено по умолчанию. Без него данные живут в RAM до перезапуска сервера или 12 часов бездействия. С ним сохраняются роль и последние 30 текстовых пар вопрос/ответ. Изображения и звук не сохраняются этой функцией.
- В запрос входят последние четыре полные пары в пределах 10 000 символов и до пяти найденных фрагментов по 1000 символов. История ИИ не считается подтверждённым личным опытом.
- Удаление сессии не восстанавливается завершением уже отправленного запроса. Удаление материала сбрасывает индекс; сессия с удалённым материалом требует нового выбора.
- Удаление материала не удаляет старые ответы, цитировавшие его: удалите соответствующие сохранённые сессии отдельно. Удаление в JobGhost не удаляет данные у внешнего провайдера или в ChatGPT.
- Изоляция контекста проверена для API-сессий. Одна браузерная вкладка ChatGPT сохраняет старую переписку — для чистого контекста нужен новый чат.
- Поиск и инструкции снижают риск выдуманных фактов, но не гарантируют их отсутствие. Сверяйте источник перед использованием ответа.
- Бесплатные модели OpenRouter могут быть медленными, недоступными или нарушать схему JSON. Ошибочный/неполный план не выдаётся за готовый, автоматического платного fallback нет.

## Карта реализации для агентов

```text
Speech: существующие speech.py / RealtimeTranscriber
Vision: ручной JPEG, существующий region-capture
               ↓
Context Builder: services/context.py
  ├─ роль: резюме либо custom prompt
  ├─ Memory: последние реплики конкретного session_id
  └─ Knowledge: services/knowledge.py → FastEmbed → Qdrant RAM
               ↓
Answer: services/ai_provider.py → SSE + metadata sources
               ↓
ChatAnswer / AnswerHistory

Training: api/preparation.py → coach / plan → Preparation.tsx
```

Это модули одного конвейера, а не несколько платных LLM-агентов. На обычный вопрос нужен один вызов генерации; поиск не использует API-токены.

Новые таблицы `knowledge_documents`, `assistant_context_sessions` создаются существующим `Base.metadata.create_all`; прежние таблицы не изменяются.

Контракты:

- `POST /api/ai/session/start`: добавлены `document_ids`, `save_history`; ответ содержит `session_id`.
- `POST /api/ai/ask`: `session_id` делает сохранённую конфигурацию сессии авторитетной. Без него разрешены `document_ids` и прежняя роль. SSE `done.sources` содержит название, тип, источник, номер фрагмента и score поиска.
- `/api/preparation/status`, `/load`, `/documents`, `/documents/{id}`, `/vacancy`, `/coach`, `/plan`, `/sessions`, `/sessions/{id}` — локальная origin-защита как у других новых API.
- `stream_answer`: внутренние `max_tokens`, `json_schema` для структурированной подготовки. OpenAI получает `text.format`, OpenRouter — `response_format`, `require_parameters=true` и до трёх бесплатных моделей с `structured_outputs`. Каждая часть ограничена двумя минутами. Обычный чат сохраняет прежние лимиты и потоковую печать.

## Проверки

`backend/tests/test_preparation.py`: удаление/очистка контактов, origin, opt-in, восстановление сохранённой сессии, изоляция двух сессий, источники, отказ после удаления, custom без резюме, оценка 0–10, ровно 30 вопросов, запрет посторонних URL, реальный Qdrant с тестовыми embeddings.

`frontend/src/pages/Preparation.test.tsx`: сохранение выключено по умолчанию, применение роли, план только с вакансией, ошибка ИИ без выдуманной оценки.

`backend/.venv/Scripts/python.exe scripts/test-context.py`: реальная локальная multilingual модель на синтетическом RU/EN примере.

`scripts/test-training-live.py --confirm-isolated [--provider openai|openrouter] [--plan]`: только для отдельно запущенного тестового сервера на 8765! Меняет настройки этого сервера, использует уже сохранённый ключ, отправляет синтетический текст и расходует API-кредиты. Не запускать против рабочей базы пользователя.

Официальные основания: [Qdrant local mode](https://github.com/qdrant/qdrant-client#local-mode), [FastEmbed](https://qdrant.tech/documentation/fastembed/), [OpenAI JSON mode и необходимость проверки схемы](https://developers.openai.com/api/docs/guides/structured-outputs#json-mode).
